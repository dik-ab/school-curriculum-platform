# Project 01: 美容室予約システム「Lumina Reserve」

株式会社Luminaは、都内で美容室「Lumière(リュミエール)」を1店舗運営しています。予約は電話と紙台帳で管理しており、聞き間違いによるダブルブッキングと、営業時間外に予約できないことが課題です。あなたは入社1人目のエンジニアとして、Web予約システムをMVPから作ります。

- 仕様リポジトリ: [curriculum-project-salon-reservation](https://github.com/dik-ab/curriculum-project-salon-reservation)
- 目安: 6〜8週(AI駆動前提)
- 必要なもの: ローカル環境のみ(AWSデプロイは任意課題)

## このプロジェクトで身につくこと

SNS開発が「機能を並べる」訓練だったのに対し、予約システムは**ビジネスルールをコードに落とす**訓練です。

| テーマ | 具体的には |
| --- | --- |
| ドメインロジック | 営業時間 ∩ スタッフのシフト − 既存予約、から空き枠を計算する |
| トランザクション | 同じ枠への同時予約をSELECT FOR UPDATEで防ぎ、競合テストで証明する |
| ロール別権限 | customer / staff / adminで見えるもの・できることを分ける |
| 状態管理 | 予約のステータス遷移(confirmed → cancelled / completed / no_show)を正しく縛る |
| 管理画面 | 予約ボード、電話予約の手動登録、売上サマリという「業務の道具」を作る |

予約・在庫・スケジュールの重複防止は、業種を問わず実務で頻出するパターンです。面接で「二重予約をどう防ぎましたか」に手を動かした経験で答えられるようになります。

## 主な機能(Must)

- 顧客のサインアップ(メール確認)とログイン、スタッフ・店長は招待制
- メニュー管理(所要時間・価格)、スタッフ管理、対応メニューの紐付け
- 営業時間・定休日、週次シフトパターンとシフト例外
- 空き枠検索(日付+メニュー複数+指名任意 → 30分刻みの空き枠)
- 予約の作成・変更・キャンセル(開始24時間前ルール)、二重予約防止
- マイページ、予約ボード(日別タイムライン)、電話予約の手動登録
- 顧客一覧と施術メモ(カルテ)

詳細は仕様リポジトリの `docs/requirements.md` を参照してください。DB設計(12テーブル)、API設計、画面定義、インフラ構成図もすべて `docs/` にあります。

## マイルストーン

| マイルストーン | 内容 | issue数 |
| --- | --- | --- |
| M1 認証と管理基盤 | 環境構築、認証、招待制、メニュー・スタッフ管理 | 7 |
| M2 シフトと空き枠 | 営業時間、シフト、空き枠計算API(このプロジェクトの心臓部) | 5 |
| M3 予約コア | 予約作成(競合テスト込み)、変更・キャンセル、予約ボード | 7 |
| M4 運用と仕上げ | カルテ、売上サマリ、リマインダーメール、CI、README整備 | 5 |

M2の空き枠計算とM3の二重予約防止が難所です。仕様リポジトリの `reservation-domain` スキルにアルゴリズムの仕様と実装指針があるので、AIに読ませてから設計してください。

## 始め方

1. [仕様リポジトリ](https://github.com/dik-ab/curriculum-project-salon-reservation)で「Use this template」→ 自分のリポジトリを作る
2. cloneして `claude` を起動し、`project-onboarding` スキルでプロジェクトの全体像を掴む
3. `setup-github-project` スキルでissueとマイルストーンを自分のリポジトリに複製する
4. M1-01から着手する。進め方の型は[AI駆動開発の型(応用編)](/advanced/ai_driven_flow/)のとおり
