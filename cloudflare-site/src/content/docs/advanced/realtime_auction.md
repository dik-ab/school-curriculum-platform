# Project 05: リアルタイムオークション「Lumina Market」(選択)

Lumina社は社員150人に成長。社内チャットの「譲ります/欲しいです」投稿はすぐ流れて埋もれます。福利厚生として社内オークション/フリマ「Lumina Market」を作ることになりました。盛り上がるように、入札はリアルタイムで反映します。

- 仕様リポジトリ: [curriculum-project-realtime-auction](https://github.com/dik-ab/curriculum-project-realtime-auction)
- 目安: 4〜6週(AI駆動前提)
- 必要なもの: ローカル環境のみ

## このプロジェクトで身につくこと

SNSのDMで触れたWebSocketを、**負けたら困る業務ロジック**に昇格させるプロジェクトです。

| テーマ | 具体的には |
| --- | --- |
| 同時入札の整合性 | 「高い方だけが勝つ・同額は先着」を条件付きUPDATEで保証し、並列100入札のテストで証明する |
| リアルタイム配信 | 出品ごとのroomに現在価格・入札履歴・残り時間・閲覧人数をブロードキャストする |
| 締切との競合 | 終了3分前の入札で自動延長(+3分、上限30分)、締切後の入札は必ず拒否する |
| スケジューラ | 締切処理、落札確定、流札。ラスト入札との競合を正しく裁く |
| 検索とページング | キーワード+カテゴリ+終了間近/人気ソート |

オークションは「同時実行 × リアルタイム × 締切」が全部入った題材で、作っていて面白く、デモ映えするのでポートフォリオの掴みに向いています。

## 主な機能(Must)

- 会社ドメイン限定のサインアップ、出品(画像4枚・開始価格・入札単位・即決価格・終了日時)
- 一覧・検索・ソート、adminによる不適切出品の停止
- 入札(現在価格+入札単位以上、同額先着)、即決、入札負けの即時通知
- 出品詳細のリアルタイム更新(WebSocket)、切断→再接続の状態復元
- 自動延長、締切スケジューラ、落札→受け渡し→完了の取引フロー
- マイページ(出品中/入札中の勝ち負け/落札履歴)、ウォッチリスト

## マイルストーン

| マイルストーン | 内容 | issue数 |
| --- | --- | --- |
| M1: 出品と検索 | 認証(ドメイン制限)、出品CRUD+画像、検索・ソート | 5 |
| M2: 入札コア | 入札API(競合テスト)、即決、締切スケジューラ | 5 |
| M3: リアルタイム | WebSocket基盤、ブロードキャスト、自動延長、再接続 | 5 |
| M4: 取引と仕上げ | 取引フロー、ウォッチリスト、代理入札、CI | 5 |

M2の入札APIが心臓部です。`bidding-consistency` スキルに、入札の不変条件、条件付きUPDATE/行ロック/楽観ロックの比較、並列入札テストの書き方、WebSocketイベント設計があります。

3. 進め方は[AI駆動開発の型(応用編)](/advanced/ai_driven_flow/)のとおり
